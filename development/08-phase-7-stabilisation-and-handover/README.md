## 10. Phase 7 – Stabilisation and Developer Handover

### 10.1 Objective
Stabilise the release and leave the client with a team and documentation able to maintain and extend the solution.

### 10.2 Stabilisation
Monitor errors, performance, business transactions and integrations; fix release-related defects; update the debt register; review incidents with the support team. The operational owner works first line, with the consultant supporting.

**Deliverable:** Stabilisation Report.

### 10.3 Documentation Package
Architecture and ADRs, component and module specs, content and data models, API and integration specs, environment and configuration guide, pipeline guide, standards, test strategy and suites, runbooks, troubleshooting guides, known limitations and technical debt. Secrets are transferred only through approved secure mechanisms.

**Deliverable:** Technical Documentation Repository.

### 10.4 Knowledge Transfer
Architecture walkthrough, code walkthroughs, pipeline and deployment demonstrations, debugging and troubleshooting sessions, supervised changes by the receiving team. Keep training records.

**Deliverable:** Knowledge Transfer Record.

### 10.5 Ownership Transfer
Repositories, pipelines, environments, accounts, licences, vendor relationships and credentials are owned by the client.

### 10.6 Future Roadmap
Debt reduction, upgrade path and product lifecycle dates, performance improvements, new capabilities, with rationale, dependencies, priority and risks.

**Deliverable:** Engineering Roadmap.

### 10.7 Consultant Exit and Operational Ownership
**Hard exit condition.** The consultant cannot formally exit until the client has a **named, accountable team or provider** able to maintain and release the solution, with written acceptance, coverage hours, responsibilities for code, pipelines, releases and vendor escalation, and custody of credentials and accounts. The owner is appointed by E6 so that they take part in release and stabilisation.

**Fallback if the client cannot appoint in time:** a time-boxed, separately contracted bridging period with a fixed end date, or a signed risk acceptance by the accountable executive. The consultant does not become the default development team.

### 10.8 Phase 7 Exit Criteria (Gate E7)
**Entry condition:** named maintaining owner (or executed fallback).
- Production stable for the agreed period.
- Documentation and knowledge transfer complete and signed.
- Access and ownership transferred.
- Engineering roadmap and debt register delivered.
- Handover accepted.

**Final Deliverable:** Signed Developer Handover and Closure Report.
