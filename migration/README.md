# Migration

Two complete handbooks cover migration to and from Adobe Digital Experience Platform (DXP). Both use a seven-phase lifecycle, approval gates, templates, checklists and diagrams, and both end with the operational-owner exit rule.

| | [Upscaling](upscaling/README.md) | [Downscaling](downscaling/README.md) |
|---|---|---|
| **Direction** | Existing platforms → Adobe DXP | Adobe DXP → WooCommerce, PrestaShop, Shopify or custom |
| **Handbook** | Enterprise Adobe DXP Migration Handbook v1.1 | Adobe DXP Downscale Playbook v1.0 |
| **Gates** | G1–G7 | D1–D7 |
| **Typical driver** | Growth, enterprise content and commerce, personalisation, data unification | Cost at renewal, over-specification, simplification, lost skills, strategy change |
| **Critical early question** | Which Adobe products and deployment models does the business actually need? | What can be exported, under what entitlement, and when does the Adobe contract require notice? |
| **Biggest risks** | Under-designed architecture, data integrity, integration complexity | Missed notice dates, lost capability, lost data, lost search traffic |
| **Closing evidence** | Named operational owner, signed handover | Named operational owner, **Adobe decommissioning evidence**, signed handover |

## Choosing a handbook

- Moving **onto** Adobe DXP: use [upscaling](upscaling/README.md).
- Moving **off** Adobe DXP, or sizing a reduction at renewal: use [downscaling](downscaling/README.md). Start with the contract and entitlement review (§2.3 and Phase 1).
- Moving between Adobe products or deployment models (for example Adobe Commerce on-premises to a cloud service): start with [upscaling](upscaling/README.md), which treats deployment-model decisions per product.
