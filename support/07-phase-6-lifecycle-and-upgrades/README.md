# PHASE 6: PLATFORM LIFECYCLE AND UPGRADE MANAGEMENT

> Part of the *Enterprise Adobe DXP Support and Operations Handbook* v1.0 (Review Draft). Section numbers (§) refer to the handbook's original numbering; see the README at the root of this folder for the section map.

## 9. Phase 6 – Platform Lifecycle and Upgrade Management

### 9.1 Objective
Stay supported, secure and current without disruptive surprises.

### 9.2 Release and Deprecation Tracking
Track Adobe release notes, security bulletins, deprecations and end-of-support dates for every product, version and third-party component (verify sources per §1.5). Record them in a lifecycle calendar.

### 9.3 Impact Assessment
For each relevant release or patch: affected components, custom code and integrations, risk, test effort, rollout plan and business timing.

### 9.4 Patch and Upgrade Execution
Plan, test in lower environments, schedule, deploy through the change process, verify, and review. Prefer small, regular updates over rare large ones. Coordinate with the development team where code changes are needed.

### 9.5 Security Bulletins
Triage by severity, apply emergency patches where the risk requires, record decisions and evidence.

### 9.6 Licence and Entitlement Tracking
Renewal dates, notice periods, usage limits and entitlements, with owners and reminders.

### 9.7 Phase 6 Review Criteria (Gate S6, reviewed periodically)
- Lifecycle calendar current.
- No unsupported versions without an approved risk acceptance.
- Critical patches applied within agreed windows.
- Upgrades completed with verified outcomes.
